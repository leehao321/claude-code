# 路由器 / OpenWrt / 旁路由

目录:1. 铁律 · 2. 动手前信息收集 · 3. 刷机流程骨架 · 4. 旁路由配置 · 5. 关 DHCP 的取舍 · 6. 常见问题

本文件给**流程与原则**。具体机型的解锁方法、固件下载与刷机命令变化很大且各机型不同:**必须先去恩山检索并读完整帖,不得凭记忆给命令,也不得给没有检索到的镜像链接。** 下面的 `uci` 片段字段以所装 OpenWrt 版本文档为准。

## 1. 铁律

1. 没拿到**型号 + 硬件版本 + 当前固件版本**,不谈刷机。
2. 固件镜像名必须与设备/板型输出匹配;不匹配就不刷。
3. 先备份、再动手;变砖风险要明说,并问清有没有救砖手段(TTL 串口、编程器、官方救急模式)。
4. 刷机会丢保修、可能丢失运营商/光猫相关配置,需要用户知情。
5. 一步一验证,别一次改多项。

## 2. 动手前信息收集

已有 OpenWrt 的设备:

```sh
ubus call system board        # model、board_name、release
cat /etc/openwrt_release
```

原厂固件:后台"系统状态"页读型号和硬件版本(机身底部标签也有),并截图/记录固件版本号。

还要问:

- 目的:旁路由?主路由?只想装插件?
- 现有拓扑:光猫是否桥接、拨号在谁身上、IPv6 是否在用。
- 有没有第二个可用上网设备(刷机失败时求助、下载文件用)。

## 3. 刷机流程骨架

1. **恩山检索** `site:right.com.cn <型号> OpenWrt`(必要时加硬件版本),读完整帖,看回复里有没有"变砖/版本不对"的反馈;注意发帖时间和固件版本是否与用户当前一致。
2. **备份**:
   - OpenWrt:`sysupgrade -b /tmp/backup-$(date +%F).tar.gz`,再用 scp 拷到电脑。
   - 原厂:后台导出配置;有 SSH 权限时按帖子方法备份分区(如 `cat /proc/mtd` 查看分区,按帖子步骤 dump,**不要自己猜分区**)。
3. **校验镜像**:对照帖子或官方下载页提供的 sha256,`sha256sum <镜像>`。
4. **解锁/刷入**:严格按检索到的步骤,逐条解释;**不给检索不到的命令**。刷机过程中不断电、不拔网线、不重复点击。
5. **刷后验证**:能进入后台、`ubus call system board` 型号对、网口/无线正常,再做后续配置。
6. **恢复备份**时注意跨版本兼容,不确定先别整包恢复,手动对照迁移关键配置。

## 4. 旁路由配置

旁路由(side router / 单臂路由):接在主路由 LAN 口下,不拨号,客户端把网关(和/或 DNS)指向旁路由,由它做分流/代理。

在旁路由上(LuCI:网络 → 接口 → LAN,或用 `uci`):

```sh
uci set network.lan.proto='static'
uci set network.lan.ipaddr='192.168.1.2'      # 与主路由同网段、未被占用的固定地址
uci set network.lan.netmask='255.255.255.0'
uci set network.lan.gateway='192.168.1.1'     # 主路由地址
uci set network.lan.dns='192.168.1.1'         # 或你选定的 DNS
uci set dhcp.lan.ignore='1'                   # 旁路由上不开 DHCP,避免与主路由冲突
uci commit
/etc/init.d/network restart && /etc/init.d/dnsmasq restart
```

> 改 LAN 地址会让当前连接断开:先确认新地址与自己电脑同网段、记好新地址,并**保留一条能回到旧地址的办法**(如暂时手动给电脑设固定 IP)。

单臂模式通常还要在防火墙 LAN 区域开启 IP 动态伪装(masquerade),避免回程不对称;LuCI 在 网络 → 防火墙 → 区域 → lan → "IP 动态伪装"。验证:

```sh
ping -c 3 192.168.1.1
ping -c 3 223.5.5.5
nslookup example.com 127.0.0.1
```

客户端侧验证:把一台设备网关改成旁路由地址,`traceroute` 第一跳应是旁路由。

## 5. 关 DHCP 的取舍

用户常问"旁路由怎么把主路由的 DHCP 关掉",要先说清有两种做法:

- **A. 保留主路由 DHCP,只改它下发的网关/DNS 为旁路由地址**(主路由后台"DHCP 服务器 → 网关/DNS"选项)。好处:旁路由挂了,把选项改回即可,或让设备手动指定回主路由;风险较小。多数家庭推荐。
- **B. 关闭主路由 DHCP,由旁路由开 DHCP**(旁路由上 `uci set dhcp.lan.ignore='0'`,并确保下发的网关是旁路由/主路由)。风险:旁路由一旦挂掉或重启,全屋拿不到地址或断网,需手动给设备设固定 IP 才能恢复。

无论哪种,**同一网段只能有一个 DHCP 服务器**;改之前确认谁在下发,改完让一台设备续租并验证。具体选项位置因主路由品牌不同,必要时按其型号去恩山检索。

## 6. 常见问题

- **旁路由后部分设备打不开网页**:检查 masquerade、MTU(见 `tuning-playbook.md` 5 节)、DNS 是否被双重劫持。
- **旁路由断电全屋断网**:回到方案 A 的思路,别让关键设备强依赖旁路由;重要设备保留指向主路由的备用方式。
- **弱路由开重协议很卡**:路由器 CPU 加密能力有限,别开重协议和过多规则集(见 `proxy-recipes.md` 客户端节)。
- **刷机后 Wi-Fi 异常**:先查型号对应的无线驱动/固件版本讨论,别自己乱改国家码和功率。
