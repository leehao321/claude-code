# 路由器 / OpenWrt / 旁路由 / 软路由

目录:1. 铁律 · 2. 动手前信息收集 · 3. 刷机流程骨架 · 4. 旁路由配置 · 5. 关 DHCP 的取舍 · 6. 常见问题 · 7. 软路由与光猫

本文件给**流程与原则**。具体机型的解锁方法、固件下载与刷机命令变化很大且各机型不同:**必须先去恩山检索并读完整帖(用 OpenWrt 官方页面交叉核对),不得凭记忆给命令,也不得给没有检索到的镜像链接。** 下面的 `uci` 片段字段以所装 OpenWrt 版本文档为准。

## 1. 铁律

1. 没拿到**型号 + 硬件版本 + 当前固件版本**,不谈刷机。
2. 固件镜像名必须与设备/板型输出匹配;不匹配就不刷。
3. 先备份、再动手;变砖风险要明说,并问清有没有救砖手段(TTL 串口、编程器、官方救急模式)。**若没有救砖手段、且该路由是家里唯一上网设备**:先劝用户备好备用路由/手机热点,或确认官方救急模式可用,否则不继续。
4. 刷机会丢保修、可能丢失运营商/光猫相关配置,需要用户知情。
5. 一步一验证,别一次改多项。
6. 每条刷机/解锁命令执行前先说明作用并取得用户确认;涉及 `mtd`/`dd` 写分区的命令,先让用户贴出 `cat /proc/mtd` 输出核对分区名,逐条确认,不得凭猜测。

### 搜不到 / 读不了恩山时

- 铁律不变,不凭记忆补命令或镜像链接,也不要因此只说"不能做"——把下面能做的部分给出来。
- **仍可做**(不涉及具体机型命令):收集型号 + 硬件版本 + 当前固件版本;第 3 节第 2 步里的通用备份;已是 OpenWrt 时的第 4 节旁路由配置。
- **必须标 `[UNKNOWN]`**:解锁方法、镜像下载与 sha256 来源、刷入命令、分区 dump。给最小实验:让用户把恩山对应帖子全文(或型号 + 硬件版本 + 固件版本)贴过来,或用 `community-research.md` 的提问帖模板发帖,再按帖子逐条解释。

## 2. 动手前信息收集

**先问**:设备现在是已经跑着 OpenWrt,还是原厂固件?(能 SSH 进去且 `ubus call system board` 有输出就是 OpenWrt。)已是 OpenWrt 且只想做旁路由 → 不涉及刷机,跳过第 3 节,但仍要问完下面的拓扑问题,再按第 4 节做(含防锁死提醒)。

已有 OpenWrt 的设备:

```sh
ubus call system board        # model、board_name、release
cat /etc/openwrt_release
```

原厂固件(通常还没有 SSH):后台"系统状态"页读型号和**硬件版本**(机身底部标签也有),并记录固件版本号。**硬件版本** = 同一型号的不同改版(常写作型号后的 v1/v2/A1/B1),不同版本板子可能完全不同、镜像不能通用。

还要问:

- 目的:旁路由?主路由?只想装插件?
- 现有拓扑:光猫是否桥接、拨号在谁身上、IPv6 是否在用。
- 有没有第二个可用上网设备(刷机失败时求助、下载文件用)。

## 3. 刷机流程骨架

1. **恩山检索** `site:right.com.cn <型号> OpenWrt`(必要时加硬件版本),读完整帖,看回复里有没有"变砖/版本不对"的反馈;注意发帖时间和固件版本是否与用户当前一致。同时用 OpenWrt 官方页面(Table of Hardware、wiki、forum)交叉核对型号、硬件版本、固件版本与刷机方法;两边不一致时,以官方版本要求为准并告知用户。
2. **备份**:
   - OpenWrt:`sysupgrade -b /tmp/backup-$(date +%F).tar.gz`,再用 scp 拷到电脑。
   - 原厂:后台导出配置;有 SSH 权限时按帖子方法备份分区(`cat /proc/mtd` 查看分区,按帖子步骤 dump,**不要自己猜分区**)。
3. **校验镜像**:`sha256sum <镜像>`,sha256 优先取自 OpenWrt/厂商官方下载页;若只有论坛帖提供,明说其可信度较低,并与官方页或多处回复交叉核对。已在 OpenWrt 上升级时,镜像放 `/tmp` 后先执行 `sysupgrade -T <镜像>` 做兼容性检查,失败就不刷,不要加 `-F` 强制。
4. **解锁/刷入**:严格按检索到的步骤,逐条解释并经用户确认(见铁律 6);**不给检索不到的命令**。刷机过程中不断电、不拔网线、不重复点击。
5. **刷后验证**:能进入后台、`ubus call system board` 型号对、网口/无线正常,再做后续配置。
6. **恢复备份**时注意跨版本兼容,不确定先别整包恢复,手动对照迁移关键配置。

## 4. 旁路由配置

旁路由(side router / 单臂路由):接在主路由 LAN 口下,不拨号,客户端把网关(和/或 DNS)指向旁路由,由它做分流/代理。

在旁路由上(LuCI:网络 → 接口 → LAN,或用 `uci`):

```sh
uci set network.lan.proto='static'
uci set network.lan.ipaddr='192.168.1.2'      # 与主路由同网段、未被占用的固定地址
uci set network.lan.netmask='255.255.255.0'
uci set network.lan.gateway='192.168.1.1'     # 主路由地址
uci set network.lan.dns='192.168.1.1'         # 或你选定的 DNS
uci set dhcp.lan.ignore='1'                   # 旁路由上不开 DHCP,避免与主路由冲突
uci commit
/etc/init.d/network restart && /etc/init.d/dnsmasq restart
```

> 改 LAN 地址会让当前连接断开:先确认新地址与自己电脑同网段、记好新地址,并**保留一条能回到旧地址的办法**(如暂时手动给电脑设固定 IP)。

单臂模式通常还要在防火墙 LAN 区域开启 IP 动态伪装(masquerade),避免回程不对称;LuCI 在 网络 → 防火墙 → 区域 → lan → "IP 动态伪装"。验证:

```sh
ping -c 3 192.168.1.1
ping -c 3 223.5.5.5
nslookup example.com 127.0.0.1
```

客户端侧验证:把一台设备网关改成旁路由地址,`traceroute` 第一跳应是旁路由。

## 5. 关 DHCP 的取舍

用户常问"旁路由怎么把主路由的 DHCP 关掉",要先说清有两种做法:

- **A. 保留主路由 DHCP,只改它下发的网关/DNS 为旁路由地址**(主路由后台"DHCP 服务器 → 网关/DNS"选项)。好处:旁路由挂了,把选项改回即可,或让设备手动指定回主路由;风险较小。多数家庭推荐。
- **B. 关闭主路由 DHCP,由旁路由开 DHCP**(旁路由上 `uci set dhcp.lan.ignore='0'` 或 `uci delete dhcp.lan.ignore`,并确保下发的网关是旁路由/主路由)。风险:旁路由一旦挂掉或重启,全屋拿不到地址或断网,需手动给设备设固定 IP 才能恢复。

无论哪种,**同一网段只能有一个 DHCP 服务器**;改之前确认谁在下发,改完让一台设备续租并验证。具体选项位置因主路由品牌不同,必要时按其型号去恩山检索。

## 6. 常见问题

- **旁路由后部分设备打不开网页**:检查 masquerade、MTU(见 `tuning-playbook.md` 5 节)、DNS 是否被双重劫持。
- **旁路由断电全屋断网**:回到方案 A 的思路,别让关键设备强依赖旁路由;重要设备保留指向主路由的备用方式。
- **弱路由开重协议很卡**:路由器 CPU 加密能力有限,别开重协议和过多规则集(见 `proxy-recipes.md` 客户端节)。
- **刷机后 Wi-Fi 异常**:先查型号对应的无线驱动/固件版本讨论,别自己乱改国家码和功率。

## 7. 软路由与光猫

以下只给原则。**光猫超级密码、改桥接方法、IPTV/VLAN 设置因运营商和型号而异,必须去恩山检索并读完整帖,不得凭记忆给;PVE/ESXi/Docker 里的具体网络设置命令同样先检索,不凭记忆给。**

**x86 / 虚拟机软路由**

- 先问清:宿主(实体小主机 / PVE / ESXi / 群晖 Docker)、物理网口数量、WAN/LAN 各用哪个口。
- 网口规划:WAN、LAN 分别直通物理口,或接到各自的虚拟网桥。**只有一个物理口时,不要把它整个直通给虚拟机**:宿主会失去管理网络,先确保有显示器/键盘或第二条管理通道。
- 作旁路由时,虚拟网桥、vSwitch 或 Docker 网络通常要放行混杂模式(promiscuous)或用 macvlan,具体按宿主平台检索。
- 备份与回滚:改动前先做虚拟机快照(PVE 快照/备份,ESXi 快照),并照常 `sysupgrade -b` 导出 OpenWrt 配置;改坏后回滚快照,不要在没有快照时直接改 LAN 口。
- 其余 LAN 地址、DHCP、masquerade 的原则同第 4、5 节。

**光猫桥接 / 拨号**

- 改桥接前先确认:宽带拨号账号密码在哪(找运营商确认,别猜)、有没有 IPTV/VLAN 业务、是否必须保留光猫路由功能。改桥接会让光猫不再拨号,**拨号信息拿不到就先别改**。
- 改之前备份光猫配置、记下原设置截图,并确认有手机热点等备用上网手段。
- IPv6:主路由和旁路由是否都要下发 IPv6 是个常见坑,旁路由场景下先确认是否真的需要,不需要就保持原样,避免双重下发导致部分设备绕过旁路由。具体设置按型号检索。
