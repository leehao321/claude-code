# 社区查证与提问手册

目录:1. 什么时候该查 · 2. 社区入口与选板 · 3. 怎么搜 · 4. 证据标准 · 5. 引用格式 · 6. 查不到怎么办 · 7. 提问帖模板 · 8. 脱敏清单

圈子经验更新很快:线路会换、封锁策略在变、脚本和内核版本每月都不一样。遇到"不确定是否还成立"的结论,先查再答。

## 1. 什么时候该查

- 商家/机房/线路的**当前**状态(是否换线、限速、有无新活动、近期故障)。
- **封锁与探测**相关的当前有效做法(协议、dest、端口策略)。
- 报错信息陌生,日志关键词不认识。
- 脚本/工具/面板的最新用法与已知坑。
- 特定型号路由器的固件与刷机方法。
- 结论只来自记忆,而用户会据此花钱或做不可逆操作。
- 多种修法互相矛盾。

稳定知识(BBR 原理、BDP 计算、mtr 用法、sshd 基础)不必查。

入口地址沿用上游整理,**域名会迁移**:打不开就如实记录"该站访问失败",再搜站名;不要把未核实的镜像当官方。

**按问题选板:**

- 路由器 / OpenWrt / 刷机 / 旁路由 / 软路由:恩山优先;涉及 VPS 侧再加 NodeSeek 或 NodeLoc。
- 商家口碑 / CN2 / CMIN2 / CMI / 9929 / 4837 / 家宽 / IP 纯净度:NodeSeek、HostLoc(或备用站)、IDC Flare、奶昔;英文商家纠纷再加 LowEndTalk。
- 账单 / 封号 / 滥用工单:LowEndTalk、WebHostingTalk,再加一个国内板(商家面向国内用户时)。
- 只问价格:LowEndBox / LowEndSpirit 属促销,买前必须在讨论板确认。
- 工具/协议报错:官方文档与 GitHub Issues/Discussions(Xray、sing-box、Hysteria、OpenWrt)往往比论坛帖更准,优先看。

## 3. 怎么搜

最低标准:

- **至少两个**相关社区再下场景结论;来源分歧或涉及商家当前质量时**三个**。
- 用户写中文:跑中文查询;英文板块**另用自然英文再搜一遍**,并说明哪一轨证据更强。
- 搜到后**打开最佳帖子读完**,别把搜索摘要当全部依据。

中文轨(WebSearch 写法):

- `site:nodeseek.com <商家或报错>`
- `site:nodeloc.com <话题>`
- `site:idcflare.com <话题>`
- `site:forum.naixi.net <话题>`
- `site:hostloc.com <话题>`、`site:hostloc.net <话题>`
- `site:right.com.cn <型号> OpenWrt`
- `site:linux.do <话题>`

英文轨:

- `site:lowendtalk.com <provider> <symptom>`
- `site:lowendspirit.com <provider>`
- `site:webhostingtalk.com <provider>`
- `site:lowendbox.com <provider>`

技巧:

- 关键词 1–6 个,先宽后窄:商家名 + 机房 + 现象,如 `DMIT LAX 晚高峰 丢包`。
- 报错搜最独特的一段,去掉路径和 IP。
- 页面读不了(登录墙/被拒绝)就如实告知并请用户贴内容;不换镜像、缓存绕过。

## 4. 证据标准

**优先采信:**

- 帖子里有失败命令、所做改动、以及通过的验证输出。
- 第二个用户确认同一修法。
- 线路质量、面板 bug、固件相关的帖子在最近 12 个月内(理想是近 3–6 个月)。
- 问的是语法而非商家行为时,官方文档优先。
- 对方环境(运营商、地区、时段、机型)与用户一致。

**降权:**

- 只有标题提问、没有后续。
- 优惠券/AFF/邀请链接帖且没有测试方法。
- 只有一张截图、没有命令输出。
- 需要登录才能看全、而你没能打开。
- 单个孤例:按孤例对待。
- 商家本人发帖:标 `[VENDOR]`,不算独立确认。

## 5. 引用格式

站点名 + 链接(仅当工具真的返回了) + 一句话要点 + 日期(没显示写"日期未显示")。

例:"NodeSeek 2026 年 8 月有帖反馈某机房联通晚高峰丢包,但对方是移动宽带,与你的电信环境不同 `[PROBABLE]`。"

**铁律:搜不到就说没搜到。不得编造标题、链接、日期、引文,也不得写"有用户反馈……"来填空。**

## 6. 查不到怎么办

1. 说明"没找到可靠结论"。
2. 列 2–3 个按可能性排序的假设,每个附一句依据,标 `[UNKNOWN]` 或 `[PROBABLE]`。
3. 给一个**最小实验**区分假设(换端口测一次、换协议测一次、同时段对比另一台机器)。
4. 让用户贴结果,继续收敛。
5. 实验后仍无头绪,起草提问帖。

## 7. 提问帖模板

好问题:环境写全、现象可复现、已尝试的列出、日志脱敏。

```
标题:【机型/机房】<现象一句话>,已排除 <已试方案>

【环境】
- 商家/套餐/机房:
- 虚拟化 / 系统 / 内核:
- CPU / 内存 / 带宽:
- 软件及版本(Xray / sing-box / 面板 / OpenWrt 等):
- 使用地区与运营商:

【现象】
(什么时间、什么操作、什么结果;能否复现;闲时与晚高峰有无差别)

【已排查】
1. ……(结果)
2. ……(结果)

【关键日志/测试输出】(已脱敏)
(只贴必要段落)

【想问】
(一句话说清想要什么)
```

给用户的提示:标题带关键信息,别写"求助大佬";附 NQ 或 mtr 关键结果,别只说"很卡";有进展回帖更新,留下答案。

## 8. 脱敏清单

发帖、贴日志给任何人之前逐项打码:

- 服务器 IP、域名、面板地址和端口
- UUID、密码、私钥(公钥也别随便贴)、shortId
- 订阅链接、私有仓库地址、访问令牌
- SSH 端口、用户名
- 日志里的客户端来源 IP
- 路由器:MAC、拨号账号密码、DDNS 域名、Wi-Fi 密码

确认无误再让用户发出去。
