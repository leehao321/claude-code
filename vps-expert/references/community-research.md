# 社区查证与提问手册

目录:1. 什么时候该查 · 2. 社区入口与选板 · 3. 怎么搜 · 4. 证据标准 · 5. 引用格式 · 6. 查不到怎么办(含 6b 没有联网工具) · 7. 提问帖模板 · 8. 脱敏清单

圈子经验更新很快:线路会换、封锁策略在变、脚本和内核版本每月都不一样。遇到"不确定是否还成立"的结论,先查再答。本文件是查证规则的**唯一定义处**,其他文件只引用,不重复写数字。

## 1. 什么时候该查

- 商家/机房/线路的**当前**状态(是否换线、限速、有无新活动、近期故障)。
- **封锁与探测**相关的当前有效做法(协议、dest、端口策略)。
- 报错信息陌生,日志关键词不认识(先看官方文档和 GitHub Issues,够用就不必查论坛)。
- 脚本/工具/面板的最新用法与已知坑。
- 特定型号路由器的固件与刷机方法。
- 结论只来自记忆,而用户会据此花钱或做不可逆操作。
- 多种修法互相矛盾。
- 用户拿来两个结论相反的帖子问"该信谁":标 `[CONTESTED]`,两边的环境和日期都列出,给出倾向与理由;用户自己的环境仍是 `[UNKNOWN]`,倾向写成"先测什么"。

稳定知识(BBR 原理、BDP 计算、mtr 用法、sshd 基础)不必查。

**按问题选板:**

- 路由器 / OpenWrt / 刷机 / 旁路由 / 软路由:恩山优先,OpenWrt 官方页面交叉核对;涉及 VPS 侧再加 NodeSeek 或 NodeLoc。

- 账单 / 封号 / 滥用工单:LowEndTalk、WebHostingTalk,再加一个国内板(商家面向国内用户时)。
- 只问价格:LowEndBox / LowEndSpirit 属促销,买前必须在讨论板确认。
- 工具/协议报错:官方文档与 GitHub Issues/Discussions(Xray、sing-box、Hysteria、OpenWrt)往往比论坛帖更准,优先看,引用时核对版本与日期。

## 3. 怎么搜

**最低标准:**

- 总共**至少两个**独立的相关社区(促销帖、LowEndBox 不计入),再下场景结论;**来源分歧或涉及商家当前质量时三个**(选购比较一般属于后者,受 `buying-guide.md` 的搜索预算约束)。
- **例外(场景 E 纯路由器/OpenWrt 问题)**:以恩山为主,第二来源用 OpenWrt 官方页面(Table of Hardware、wiki、forum.openwrt.org),不要求 VPS 社区;仅当涉及 VPS 侧(回程、中转、节点)时再加 NodeSeek/NodeLoc。官方页面只用来交叉核对硬件版本与固件版本,刷机步骤仍只采信检索并读完整的帖子,不给未检索到的镜像链接或命令。设备无 OpenWrt 支持或跑厂商固件时,第二来源改为厂商官方页面。
- **中文轨与英文轨各至少搜一次**,不要求每轨各有一个社区。用户写中文:英文轨改用自然英文关键词;用户写英文:中文轨改用中文关键词搜 NodeSeek/NodeLoc/HostLoc 等。最后说明哪一轨证据更强、有无语言偏向。
- 搜到后**打开最佳帖子读完**,别把搜索摘要当全部依据。

中文轨(WebSearch 写法):

- `site:nodeseek.com <商家或报错>`
- `site:nodeloc.com <话题>`
- `site:idcflare.com <话题>`
- `site:forum.naixi.net <话题>`
- `site:hostloc.com <话题>`
- `site:right.com.cn <型号> OpenWrt`
- `site:linux.do <话题>`

英文轨:

- `site:lowendtalk.com <provider> <symptom>`
- `site:lowendspirit.com <provider>`
- `site:webhostingtalk.com <provider>`
- `site:forum.openwrt.org <model>`

技巧:

- 关键词 1–6 个,先宽后窄:商家名 + 机房 + 现象,如 `DMIT LAX 晚高峰 丢包`。
- 报错搜最独特的一段,去掉路径和 IP。
- 搜索工具不支持 `site:`,或站点被登录墙/拒绝访问时:去掉 `site:` 改用"站名 + 关键词"搜;仍打不开就记录"哪些站未能访问",请用户贴内容,并把相关结论降为 `[PROBABLE]` 或 `[UNKNOWN]`。不换镜像、缓存绕过。

## 4. 证据标准

**时效口径(唯一定义,其他文件只引用本节)**:时效性结论(线路/商家质量、面板 bug、固件、封锁策略)——首选 ≤6 个月,可接受 ≤12 个月;超过 12 个月只能当线索,引用时写"可能已过时",结论最高 `[PROBABLE]`,不单独支撑结论。语法/官方文档类问题不受此限。

**优先采信:**

- 帖子里有失败命令、所做改动、以及通过的验证输出。
- 第二个用户(不同作者)确认同一修法。
- 问的是语法而非商家行为时,官方文档优先。
- 对方环境(运营商、地区、时段、机型)与用户一致。

**不计入"最低数量",也不能单独支撑高于 `[UNKNOWN]` 的结论:**

- 只有提问、没有后续回复的帖子;水帖;纯 AFF/邀请链接帖。
- 商家本人发帖:标 `[VENDOR]`,不算独立确认。

**降权(可作线索,需其他证据配合):**

- 只有一张截图、没有命令输出。
- 需要登录才能看全、而你没能打开。
- 单个孤例:按孤例对待。

## 5. 引用格式

站点名 + 链接(仅当工具真的返回了) + 一句话要点 + 日期 + 对方环境与用户是否一致 + 标签。

格式示例(**仅为格式示范,不是真实引用,不得当作事实复用**):

> <站点名> <发帖日期或"日期未显示"> <链接:仅当工具返回了> 一句话要点;对方环境 <运营商/地区> 与用户 <一致/不一致> `[标签]`

**日期规则**:日期只取页面可见的发帖/回复时间(含正文里写明的日期);用首帖日期,若被顶起且最新回复更近则一并注明。**不得从帖子编号、URL 推断年份。** 没有可见日期就写"日期未显示":这类来源不能单独支撑 `[CONFIRMED]`,最高 `[PROBABLE]`,并在结论里注明"无法判断时效"。

**铁律:搜不到就说没搜到。不得编造标题、链接、日期、引文,也不得写"有用户反馈……"来填空。**

## 6. 查不到怎么办

1. 说明"没找到可靠结论"。
2. 列 2–3 个按可能性排序的假设,每个附一句依据,**只标 `[UNKNOWN]`**(没有来源就不是 `[PROBABLE]`)。
3. 给一个**最小实验**区分假设(换端口测一次、换协议测一次、同时段对比另一台机器)。
4. 让用户贴结果,继续收敛。
5. 实验后仍无头绪,起草提问帖。

### 6b. 没有联网工具 / 只能访问一个社区

1. 有 WebSearch/WebFetch 就**必须先实际调用**,不能在没尝试的情况下就宣布"无法联网"。只有调用失败、被拦,或确实没有这类工具,才在开头一句话说明"本次无法联网核对"或"只能访问到 <站点>"。不要静默跳过,也不要拒答。
2. 第 2 类结论(商家口碑、当前线路、封锁/探测做法、面板/脚本 bug、型号固件)只能作为"**未核对的记忆**"给方向,标 `[UNKNOWN]`;**不给**当前延迟数字、帖子标题、链接或"有用户反馈",不称"通用知识",不声称"已搜索"。
3. 能访问的独立社区不足两个时,结论最高到 `[PROBABLE]`。
4. 给用户出路:请他把相关帖子原文贴过来,或用最小实验代替查证;涉及花钱/不可逆操作的,给"买后验收/小范围试验"方案(见 `buying-guide.md`)。
5. 涉及执行第三方脚本(如 NQ)而无法核对官方 README 时,命令旁注明"未核实",请用户先去官网确认或先读脚本。

## 7. 提问帖模板

好问题:环境写全、现象可复现、已尝试的列出、日志脱敏。

```
标题:【机型/机房】<现象一句话>,已排除 <已试方案>

【环境】
- 商家/套餐/机房:
- 虚拟化 / 系统 / 内核:
- CPU / 内存 / 带宽:
- 软件及版本(Xray / sing-box / 面板 / OpenWrt 等):
- 使用地区与运营商:

【现象】
(什么时间、什么操作、什么结果;能否复现;闲时与晚高峰有无差别)

【已排查】
1. ……(结果)
2. ……(结果)

【关键日志/测试输出】(已脱敏)
(只贴必要段落)

【想问】
(一句话说清想要什么)
```

给用户的提示:标题带关键信息,别写"求助大佬";附 NQ 或 mtr 关键结果,别只说"很卡";有进展回帖更新,留下答案。

## 8. 脱敏清单

发帖、贴日志给任何人之前逐项打码:

- 服务器 IP、域名、面板地址和端口
- UUID、密码、私钥(公钥也别随便贴)、shortId
- 订阅链接、私有仓库地址、访问令牌
- SSH 端口、用户名
- 日志里的客户端来源 IP
- 路由器:MAC、拨号账号密码、DDNS 域名、Wi-Fi 密码

确认无误再让用户发出去。
